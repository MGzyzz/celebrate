Документация прототипа

Выпускной — Telegram Mini App

Это рабочий прототип на React. Вся бизнес-логика уже собрана: экраны, навигация, формы, светлая/тёмная тема, два языка и две роли. Реальных данных и интеграций пока нет — вместо них «заглушки». Эта страница показывает, куда подставлять настоящее.

i

Главная идея в одном предложении: весь контент и моковые данные лежат в app-data.js и app-i18n.js — их редактирует кто угодно без знания React. Внешние сервисы (карта, адреса, оплата) подключаются в трёх явно помеченных местах. Всё остальное — готовый интерфейс, который трогать не нужно.

Что уже работает в прототипе

  • 5 вкладок: Главная, Места, Сборы, Участники, Профиль
  • Две роли — Участник и Организатор (у организатора видны суммы, счета и управление)
  • Два языка — русский и казахский · светлая / тёмная / системная тема
  • Онбординг, формы добавления места и товара, счёт, финализация сборов
  • Состояния загрузки, пустые экраны, ошибки (демо в Профиль → UI-состояния)
01

Архитектура и файлы

Один HTML точка входа + плоский набор скриптов. Сборки нет — открывается напрямую в браузере.

Выпускной — Telegram Mini App.html
Точка входа. Все стили (CSS-токены, компоненты) и подключение скриптов. Сюда же монтируется React в #stage.
app-data.js
Все данные приложения — событие, места, сборы, товары, участники, счёт. Обычный JS-объект window.DATA. Главный файл для контента.
app-i18n.js
Все тексты интерфейса на двух языках (ru, kk). Объект window.I18N. Здесь меняются и переводятся подписи.
app-ui.jsx
UI-кит: иконки, кнопки, бейджи, карточки, поля, аватары, модалки, тосты. Переиспользуемые «кирпичики».
screens-*.jsx
Экраны, по областям: participant (главная, онбординг), places, collections, organizer, misc (профиль, состояния).
app-main.jsx
Корневой компонент App: навигация, роли, тема, язык, склейка экранов и панель Tweaks. Запускает рендер.
frames/
Вспомогательное: ios-frame.jsx (рамка телефона), image-slot.js (слот под картинку карты), tweaks-panel.jsx (панель настроек).
.image-slots.state.json
Сюда сохраняется картинка, перетянутая в слот карты (см. §04). Служебный — вручную не редактируется.
✓

Файлы .jsx компилируются прямо в браузере через Babel. Это удобно для прототипа, но в продакшене так не делают — см. §10. Логика и вёрстка при переносе сохраняются, меняется только сборка.

02

Порядок загрузки

Скрипты подключаются в строгой последовательности — данные и UI-кит должны существовать раньше, чем их используют экраны.

React + Babel→ app-i18n.js→ app-data.js→ frames/*→ app-ui.jsx→ screens-*.jsx→ app-main.jsx

Каждый компонент в конце своего файла «публикует» себя в window через Object.assign(window, {...}) — поэтому файлы видят друг друга без импортов. Если добавляете новый экран — не забудьте про эту строку в конце файла, иначе app-main.jsx его не найдёт.

в конце каждого screens-*.jsx// делает компоненты видимыми для остальных файлов
Object.assign(window, { HomeScreen, ConfirmScreen, /* ... */ });
03

Данные — app-data.js

Это «база данных» прототипа. Один объект window.DATA. Заменить моки на реальные данные = подставить сюда ответ от вашего API в той же форме.

→

В бою порядок такой: backend отдаёт JSON → вы кладёте его в DATA (или в React-state вместо DATA) → интерфейс отрисовывается сам. Названия полей и допустимые значения менять нельзя — на них завязаны цвета, фильтры и логика. Их список ниже.

event — шапка события

app-data.js → DATA.eventevent: {
  title: 'Выпускной 11 «А»',   // заголовок на Главной
  school: 'Гимназия №25',        // подпись сверху
  date: '2026-06-20',            // ISO — для расчётов
  dateLabel: '20 июня 2026',      // как показать человеку
}

places — места (карта + список)

Массив площадок. Каждая показывается меткой на карте, карточкой в списке и полной страницей. Ключевое поле — interest: оно задаёт цвет метки и бейджа.

В прототипе participants копируются в React-state при старте (app-main.jsx), чтобы организатор мог менять статусы и оплату «вживую». Текущий пользователь — это DATA.me (id: 'u1', помечается «· вы»).

myInvoice — личный счёт текущего пользователя

app-data.js → DATA.myInvoicemyInvoice: {
  total: 24500,        // итог к оплате
  common: 16000,       // общая часть (синяя)
  alcohol: 5500,       // алкоголь (красная); 0 → строка скрыта
  individual: 3000,    // индивидуальные позиции (жёлтая)
  deadline: '2026-06-12',
  paid: false,
  individualItems: [ { name: 'Именная футболка', price: 3000 } ],
}

Форматирование денег

Все суммы прогоняются через money(n) / moneyShort(n) (вверху app-data.js): целое число → «24 500 тг» с пробелами-разделителями. Хотите другую валюту/формат — правьте только эти две функции, по всему приложению изменится сразу.

04

Точки интеграции

Три места, где сейчас стоят заглушки, и которые нужно подключить к реальным сервисам. Все они помечены комментариями прямо в коде.

① Карта мест

Сейчас карта — это картинка-заглушка (скриншот Яндекс.Карт), которую можно перетащить в слот мышкой. Метки расставлены поверх неё по координатам x/y в процентах.

screens-places.jsx → PlacesScreen// слот, куда перетаскивается скриншот карты
<image-slot id="vyp-map" class="map-bg" fit="cover"
  placeholder="Перетащите скриншот Yandex Maps"></image-slot>

// метки: позиция берётся из place.x / place.y (проценты)
style={{ left: p.x + '%', top: p.y + '%' }}
✓

Для дизайнера: просто перетащите PNG/скриншот карты в область карты — он сохранится.
Для разработчика: в проде замените <image-slot> на реальную карту (Yandex JS API / MapKit), а метки рисуйте по настоящим координатам lat/lng вместо процентных x/y.

② Геосаджест адреса (форма «Добавить место»)

При вводе адреса показываются подсказки. Сейчас они берутся из захардкоженного массива.

screens-places.jsx (вверху файла)// Mock Yandex Geosuggest — заменить на реальный /v1/suggest
const GEOSUGGEST = [
  { title: 'ул. Абая, 145', sub: 'Алматы…', lat: 43.2402, lng: 76.9300 },
  // …
];

Замените фильтрацию этого массива на запрос к Yandex Geosuggest API. Формат результата сохраните: { title, sub, lat, lng } — остальной код (подстановка координат метки) останется без изменений.

③ Оплата — реквизиты Kaspi

!

Сейчас номер и имя захардкожены в тексте счёта — screens-collections.jsx, компонент InvoiceScreen: +7 707 123 45 67 (Дана Қ.). Их нужно вынести в данные (например в DATA.event.payment) и заполнять реквизитами реального организатора. Кнопка «Оплатить в Kaspi» сейчас показывает тост-заглушку — её надо привязать к Kaspi deeplink/QR.

④ Telegram Mini App SDK

Прототип нарисован в рамке телефона, но к Telegram WebApp пока не подключён. При интеграции:

  • Тема: режим system должен читать Telegram.WebApp.themeParams (сейчас слушает prefers-color-scheme в app-main.jsx).
  • Пользователь: DATA.me заполнять из initDataUnsafe.user.
  • Кнопки: нижние «BottomAction» можно заменить на нативные MainButton / BackButton.
  • Подключить скрипт telegram-web-app.js и вызвать WebApp.ready() / expand().
05

Тексты — app-i18n.js

Все надписи интерфейса в одном месте, на двух языках. Никаких текстов «зашитых» в экраны быть не должно.

app-i18n.js → window.I18Nwindow.I18N = {
  ru: { nav_home: 'Главная', save: 'Сохранить', /* … */ },
  kk: { nav_home: 'Басты',    save: 'Сақтау',    /* … */ },
};

В экранах текст достаётся функцией t('ключ'). Если ключа нет в текущем языке — берётся русский, если и там нет — показывается сам ключ.

  • Изменить текст: найдите ключ в ru (и kk) и поправьте значение.
  • Добавить новый: добавьте ключ в оба языка, затем используйте t('новый_ключ') в экране.
  • Ключи сгруппированы комментариями: // nav, // home, // places, // invoice, // organizer и т.д.
!

Несколько строк всё ещё захардкожены прямо в экранах (напр. описания вариантов участия, тексты-плейсхолдеры в формах, «· вы»). При локализации их тоже стоит перенести в I18N. Ищите по русским строкам в screens-*.jsx.

06

Цвета и темы

Вся палитра — это CSS-переменные на .app в шапке HTML. Светлая и тёмная темы — два набора одних и тех же токенов.

Акцентный цвет

Главный цвет бренда — переменная --accent. Её можно менять «на лету» в панели Tweaks или задать жёстко. В проде берите из Telegram.WebApp.themeParams.button_color, чтобы совпадать с клиентом пользователя.

Статусные цвета (важно!)

Пять смысловых цветов используются везде — для меток, бейджей, типов товаров, статусов участия:

ТокенЦветСмысл
--st-greengreenхорошо / участвует / оплачено / высокий интерес
--st-blueblueновое / общая часть / информация
--st-amberamberвнимание / спорно / думает / дедлайн
--st-redredпроблема / не участвует / алкоголь
--st-graygrayнейтрально / нет данных / не ответил

У каждого есть парный фон --st-*-bg. Связь «значение → цвет» лежит в таблицах INTEREST_COLOR, PART_COLOR (app-data.js) и COL_STATUS, ITEM_TYPE, PAY_CATS (в экранах). Меняете цвет — правите переменную, а не отдельные места.

07

Экраны и навигация

Навигация — стек на каждую вкладку (как в нативных приложениях). Управляется через ctx.nav.

app-main.jsx → SCREENS// карта имён экранов → компонентов
const SCREENS = {
  home, confirm, places, place, addplace,
  collections, collection, additem, invoice,
  participants, participant, finalize, profile, states,
};

Как переходить между экранами

  • ctx.nav.push('place', { id }) — открыть экран поверх текущего
  • ctx.nav.pop() — назад
  • ctx.nav.setTab('places') — переключить нижнюю вкладку

Объект ctx прокидывается во все экраны и содержит: t (переводы), data (=DATA), role, nav, toast(), fmtDate(), daysLeft(), состояние участия и участников. Это «общая шина» приложения.

i

Роль (ctx.role) переключает поведение: например ParticipantsScreen показывает упрощённый список участнику и полную панель с суммами — организатору. Меняется в Профиле или панели Tweaks.

09

Панель Tweaks

Панель настроек прототипа (включается в тулбаре). Для демонстрации, не часть продукта.

Позволяет на лету менять: акцентный цвет, тему, роль, язык, ширину экрана устройства. Настройки задаются в app-main.jsx внутри <TweaksPanel> и значения по умолчанию — в TWEAK_DEFAULTS. В продакшен-сборку панель не переносится.

10

Чек-лист к продакшену

Что нужно сделать, чтобы прототип стал боевым приложением.

  1. Перенести на сборку
    Заменить Babel-в-браузере на нормальную сборку (Vite / esbuild), .jsx → собранный бандл. Логика и вёрстка переносятся как есть.
  2. Подключить API вместо DATA
    Места, сборы, товары, участники, счёт грузить с backend. Сохранить структуру и названия полей из §03.
  3. Реальная карта и геосаджест
    Заменить image-slot на карту, моковый GEOSUGGEST — на Yandex Geosuggest API (§04).
  4. Оплата
    Вынести реквизиты Kaspi в данные, привязать кнопку к Kaspi deeplink/QR, подтверждение оплаты — на backend.
  5. Интеграция с Telegram
    Подключить telegram-web-app.js: тема, пользователь, нативные кнопки (§04).
  6. Дочистить тексты
    Перенести оставшиеся захардкоженные строки в I18N, проверить казахский перевод.
  7. Связать товары со сбором
    Убрать хардкод col.id === 'c1', грузить позиции по реальному collectionId.
